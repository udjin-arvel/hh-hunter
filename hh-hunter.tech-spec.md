# Техническое задание (ТЗ) на разработку Chrome-расширения «HH-Hunter»

**Версия:** 1.0  
**Дата:** 13.07.2026  
**Тип продукта:** Браузерное расширение (Manifest V3)  
**Целевая платформа:** Google Chrome, Edge (Chromium)  

---

## 1. Цель разработки
Создать инструмент для соискателей, позволяющий в 2 клика генерировать персонализированные сопроводительные письма под конкретные вакансии на HeadHunter. Расширение должно использовать LLM DeepSeek для семантического анализа вакансии, выявления скрытых требований и «упаковки» опыта кандидата в убедительный текст без фактических искажений.

---

## 2. Целевая аудитория
Соискатели всех специальностей (IT, маркетинг, производство, финансы), которые:
- Откликаются на 5+ вакансий в день и устают писать типовые тексты.
- Хотят повысить конверсию откликов за счет попадания в корпоративную культуру компании.

---

## 3. Функциональные требования (Модули)

### Модуль 1. Управление профилем пользователя
- **Экран:** Вкладка «Профиль» в попапе расширения.
- **Поля (все — опциональны):**
  1. Имя пользователя (текстовое поле).
  2. Ссылка на портфолио / резюме / LinkedIn / GitHub (текстовое поле).
- **Логика:**
  - При вводе ссылки расширение делает GET-запрос к указанному URL (с учетом CORS-ограничений, либо через `background.js` с изменением User-Agent) и пытается извлечь текстовый контент страницы (для контекста). *Если парсинг невозможен (закрытая страница) — расширение предлагает пользователю вручную вставить текст своего опыта в текстовое поле «Достижения и навыки».*
  - Данные сохраняются в `chrome.storage.local` в формате JSON: `{ name, portfolioLink, portfolioText, achievements }`.

### Модуль 2. Импорт вакансии (Сканер)
- **Экран:** Вкладка «Генератор».
- **Способы активации (2 варианта):**
  1. **Кнопка «Сканировать текущую вкладку»** — расширение определяет, открыта ли страница вакансии hh.ru (URL содержит `hh.ru/vacancy/`), и вытягивает её ID.
  2. **Поле ввода ссылки** — пользователь вручную вставляет URL вакансии.
- **Работа с HH API:**
  - Расширение парсит ID вакансии из URL (`https://hh.ru/vacancy/123456789` → ID `123456789`).
  - Отправляет запрос к публичному API: `GET https://api.hh.ru/vacancies/{id}`.
  - Маппинг полученных данных в локальный объект `Vacancy`:
    - `title` (название)
    - `company_name` (название компании)
    - `company_type` (тип: стартап / крупный бизнес / госсектор — из описания или поля `type`)
    - `description` (полный HTML-текст, очищенный от тегов)
    - `key_skills` (массив навыков)
    - `experience_required` (требуемый опыт)
    - `employment` (формат работы: удаленно / офис / гибрид)
- **Обработка ошибок:** Если ID не найден или API вернул 404 — уведомление «Вакансия не найдена или недоступна».

### Модуль 3. Настройки генерации (Форма с дефолтами)
Перед генерацией пользователь видит форму с предзаполненными значениями:

| Поле | Тип | Дефолтное значение | Описание |
| :--- | :--- | :--- | :--- |
| **Стиль письма** | Выпадающий список (Dropdown) | «Деловой» | Варианты: «Деловой» (сухо, по факту), «Эмоциональный» (энтузиазм), «С акцентом на цифры» (продуктовый). |
| **Длина письма** | Выпадающий список / Слайдер | «Среднее» | «Краткое» (50 слов), «Среднее» (100 слов), «Подробное» (180 слов). |
| **Дополнительный фокус** | Текстовое поле | *пусто* | Необязательное поле. Пример: «Сделайте акцент на моем опыте управления распределенными командами». Это значение подставляется в промпт как дополнительный приоритет. |

### Модуль 4. Генерация (Ядро на базе DeepSeek)
- **Триггер:** Кнопка «Сгенерировать письмо».
- **Процесс (последовательность действий):**
  1. Сбор контекста: `Profile (имя + текст портфолио) + Vacancy (все поля) + Settings (стиль/длина/фокус)`.
  2. Формирование **структурированного промпта** для DeepSeek (см. раздел 6. Промпт-инжиниринг).
  3. Отправка асинхронного запроса к `https://api.deepseek.com/v1/chat/completions` (модель `deepseek-chat`).
  4. Получение ответа в формате JSON (чтобы программно разделить части).
- **Задачи DeepSeek в одном запросе (обязательный вывод):**
  1. **«Скрытые ключи» (Hidden Gems):** выделить 2–3 неочевидных требования (например, «стрессоустойчивость в мультизадачности» или «гибкость к смене приоритетов»), которые не указаны в блоке Hard Skills, но вытекают из описания.
  2. **«Уникальная точка пересечения» (Unique Intersection):** найти ровно 1 связку между опытом пользователя (из портфолио) и скрытым ключом вакансии. *Пример: «В вакансии требуют управление изменениями, а у вас был проект по внедрению новой CRM — это идеальный мостик»*.
  3. **Тело письма:** текст, адаптированный под тон компании (стартап — драйвово, корпорация — формально-вежливо, госсектор — канцелярски).
- **Критическое ограничение:** Генерация должна избегать откровенной лжи (галлюцинаций). Если у пользователя нет требуемого навыка — DeepSeek должен предлагать сделать акцент на смежном навыке или обучаемости, а не выдумывать проекты.

### Модуль 5. Вывод и взаимодействие
- **Визуализация результата:** Расширение показывает 3 логических блока:
  1. **«Уникальная точка пересечения»** (выделено цветом) — для понимания стратегии письма.
  2. **«Готовое письмо»** (основное поле с текстом).
  3. **«Скрытые ключи вакансии»** (маленький спойлер/подсказка) — для обратной связи пользователю.
- **Кнопки управления:**
  - «Скопировать письмо» (записывает только тело в буфер обмена).
  - «Сгенерировать заново» (с теми же настройками, но с новым сидом для DeepSeek, чтобы получить вариативность).
  - «Открыть отклик на HH» (переход на страницу отправки отклика на данную вакансию).

## 4. Нефункциональные требования
- **Скорость:** Время ответа DeepSeek не должно превышать 15 секунд (использовать streaming, если возможно, либо спиннер с прогрессом).
- **Безопасность:** API-ключ DeepSeek **не** вшивается в код. Пользователь вводит свой ключ при первом запуске (хранится в `chrome.storage.local` в зашифрованном виде или в открытом — на усмотрение, но в ТЗ указываем, что ключ никуда не отправляется кроме как DeepSeek).
- **Конфиденциальность:** Все данные (резюме, портфолио) обрабатываются локально и покидают компьютер только в виде промпта, отправляемого в DeepSeek. Политика должна быть описана в описании расширения.
- **Разрешения (Permissions):** Минимально необходимые:
  - `storage` — для сохранения настроек.
  - `activeTab` — для получения URL текущей вкладки.
  - `scripting` — для внедрения скриптов на страницу hh.ru (если нужен парсинг DOM вместо API).
  - `https://api.hh.ru/*` и `https://api.deepseek.com/*` — в host_permissions.

## 5. Пользовательские сценарии (UI/UX)

### Главный экран (Popup)
- **Таб-навигация:** «Профиль» | «Генератор» | «Настройки API».
- **Шаг 1 (Профиль):** Пользователь вносит данные и нажимает «Сохранить». Появляется превью сохраненного текста (первые 200 символов).
- **Шаг 2 (Генератор):** 
  - Если активная вкладка — вакансия HH, кнопка сканирования подсвечивается зеленым.
  - Если нет — активна только кнопка «Вставить ссылку».
- **Шаг 3 (Настройки):** Раскрывающаяся панель «Параметры письма» со значениями по умолчанию.
- **Шаг 4 (Результат):** Появляется после генерации. Текст письма можно редактировать прямо в поле расширения (для ручных правок).

### Состояния загрузки
- Отображение индикатора прогресса: «Анализ требований...» -> «Поиск точек пересечения...» -> «Генерация текста...».

## 6. Детальный промпт-инжиниринг (для разработчика)

В ТЗ необходимо зафиксировать структуру промпта, чтобы обеспечить качество. Используйте **System Prompt** + **User Prompt**.

**System Prompt (жесткий):**
> Ты — опытный карьерный консультант и копирайтер. Твоя задача — написать сопроводительное письмо на русском языке. Запрещено выдумывать опыт, которого нет в данных кандидата. Если навык не совпадает — перенаправляй внимание на смежные компетенции или готовность к обучению. Структура ответа всегда должна быть строго в формате JSON: {"hidden_keys": ["key1", "key2"], "unique_intersection": "текст", "letter": "текст письма"}.

**User Prompt (шаблон с подстановкой):**
> **Данные кандидата:** Имя: {name}. Опыт и проекты: {portfolio_text}.
> **Данные вакансии:** Компания: {company_name} (тип: {company_type}). Требования: {description}. Навыки: {key_skills}.
> **Пожелания пользователя:** Стиль: {style}. Длина: {length}. Дополнительный фокус: {user_focus}.
> *Инструкция:* Выдели скрытые ключи. Найди 1 идеальную точку пересечения. Напиши письмо, адаптируя тон под тип компании.

## 7. Технический стек и архитектура

- **Манифест:** Manifest V3.
- **Фреймворк:** React (для динамического попапа) + TypeScript.
- **Сборщик:** Vite или Webpack (с поддержкой HMR для разработки).
- **Хранилище:** `chrome.storage.local`.
- **Сетевые запросы:** Нативные `fetch` через Service Worker (`background.js`).
- **API:**
  - HH.ru Public API (без авторизации, лимит ~1000 запросов/час).
  - DeepSeek API (ключ пользователя, модель `deepseek-chat`, температура 0.7 для креативности).

## 8. Критерии приемки (Done Done)

1. При вставке ссылки на портфолио расширение сохраняет текст в локальном хранилище.
2. Расширение корректно вычленяет ID вакансии из URL любой вариации (hh.ru/vacancy/*, hh.ru/vacancy/*#hash и т.д.).
3. Форма генерации отображает дефолтные значения (стиль «Деловой», длина «Среднее»).
4. После клика «Сгенерировать» поле вывода заполняется текстом менее чем за 20 секунд.
5. В ответе DeepSeek строго присутствуют 3 раздела: скрытые ключи, точка пересечения, письмо.
6. Сгенерированное письмо **не содержит** прямого копирования требований из вакансии (уникальность текста > 70% по тональности).
7. При нажатии «Скопировать» в буфер попадает только текст письма (без JSON-разметки).

## 9. Ограничения и зоны риска
- **CORS при парсинге портфолио:** Если сайт портфолио блокирует запросы с расширения, необходимо реализовать fallback в виде ручного ввода текста (textarea «Ваши ключевые достижения»).
- **Токенизация:** Длинные описания вакансий (> 4000 токенов) могут перегрузить контекст DeepSeek. Необходимо ограничить длину описания, отправляемого в промпт (обрезать до 3000 символов).
- **Кэширование:** Не кэшировать ответы DeepSeek для разных вакансий, чтобы избежать повторов.
